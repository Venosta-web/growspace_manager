# Crop Steering Restores Its Day and Starts Behind an Inhibit

**Status:** Accepted

A restart during the lit period used to hand the [[Steering Phase Machine]] a blank day: no record that P1 had completed, and no last shot to measure a cooldown from. The first tick therefore re-entered the P1 ramp with neither a cooldown nor the [[Infiltration Gate]] (both sit behind "there was a last shot"). In P2 the substrate sits below `target_vwc_percent` by design, so a restart mid-P2 fired a P1 shot every P1 interval until the planned dryback was gone (#786).

Two facts now survive a restart, both on the growspace's `SubstrateHistory` beside the [[SubstrateTracker]]'s pending windows: `last_confirmed_shot_at`, the moment the pump last confirmed ON for an irrigation cycle, and `p1_completed_on`, the local date P1 reached its target. The tracker's own timestamps could not serve. `pending_overnight_peak_ts` moves forward with every settling reading after a shot, and `record_shot` runs when a shot is _requested_, not when the pump confirms it — a cycle the Pump Cycle Gate then skipped would read as a shot. The coordinator's `last_cycle_timestamp` reads and writes the persisted field directly rather than keeping a copy, so the value a cooldown uses and the value a restart restores cannot disagree. Both are written through a debounced save the moment they change, because Home Assistant flushes a pending delayed save on shutdown but never unloads the integration, so in-memory state alone does not survive a restart. The machine restores the completion date only when it is today; its `restore()` also marks the lights-on date guard as run for today so the first P0/WINDOW tick does not clear what was just restored. The midnight `reset()` is unchanged, and it has no persisted state to clear: a stored date from yesterday simply never matches.

After any start or reload, every automatic cycle is held by the **Startup Inhibit** — the controller reports `inhibited` with reason `startup_inhibit` — until both `startup_grace_minutes` (default 5) have elapsed and every control sensor has reported a usable value since the start. The control sensors are the substrate moisture sensor while crop steering drives the pump, plus every configured irrigation tank. "Reported" reads the state's `last_reported`, which moves on a report that repeats the previous value, so a steady sensor still counts once it speaks. The inhibit applies to scheduled cycles and drains as well as steering shots, because the controller state is per growspace, not per mode. It latches clear for the life of the coordinator: a sensor that drops out afterwards is a stale-sensor problem, not a startup one. A manual run is not held, since it is an explicit human action, but it still passes every other gate. Missed shots are never replayed: the steering tick simply decides afresh once the inhibit lifts, and the persisted last shot still bounds its cooldown. The steering machine withholds a shot under the inhibit itself (`suppressed_by: "startup"`, checked ahead of the cooldown), so the substrate tracker and the composer never record a shot that the Pump Cycle Gate would then refuse. The gate carries the same rule for the schedule path.
