# An Unreadable Tank Fails Closed, and Says So

**Status:** Accepted

With `pause_on_low_tank` on — the default — a tank whose sensor was unavailable used to be left out of the [[Pump Cycle Gate]]'s readings, "matching the previous behaviour of skipping unreadable tanks rather than treating them as low". The gate therefore saw no low tank and fired. A dead tank probe is exactly the moment the level is unknown, so the protection a grower had switched on was absent precisely when it mattered, and the pump could run dry (#790).

The gate now refuses a cycle with `TANK_UNKNOWN` when any configured tank is at an [[Unknown Tank Level]]: unavailable, **stale** (its `last_reported` has not moved for `stale_after_minutes`, default 120) or implausible (outside 0–100 %). Stale is not optional. Many sensors never turn `unavailable` when they die: ZHA waits hours before it marks a device unavailable, and an MQTT or Zigbee2MQTT sensor without availability reporting simply freezes on its last value, which is the failure a grower is least likely to notice. The window is long by default because staleness has one false positive it cannot tell apart: a sensor that reports only when the level changes, on a tank nobody draws from overnight. For such a sensor `stale_after_minutes: 0` turns staleness off for that tank; unavailable and implausible readings still fail closed. The rule covers scheduled, steering and manual cycles alike, because all three pass the same gate and a grower standing at the tank can see its level better than the pump can; the escape hatch is `pause_on_low_tank: false`, which keeps today's behaviour and was already the explicit opt-out. A per-run override for manual cycles was considered and rejected: it would be the first "force" path through the gate, and that deserves a decision of its own.

A short probe dropout should not stop a tent. The refusal therefore waits `tank_unknown_grace_minutes` (default 10) from the moment the level stopped being trustworthy, and in the meantime the last valid reading stands in, so a tank that was low stays low. For a stale tank the grace period starts when it went stale, not when it last reported, so the two windows do not add up to a surprise. A tank that has not read validly since the start has no last reading to hold, and is refused at once; the [[Startup Inhibit]] already holds automatic cycles in that window, so the difference is felt only by a manual run, which is the case that must not fire blind.

**Failing closed is only safe if somebody hears about it.** A refusal alone swaps a dry pump for dry plants: a probe that dies at ten at night stops watering until the grower happens to look. So every configured tank is also watched on its own, on a timer rather than on cycles, since a stale sensor produces no event to react to. Once a tank has been unknown for the grace period, one **Tank Offline Alert** goes out — a push on its own notification tier and a persistent notification — whether or not a cycle is due, and whether or not `pause_on_low_tank` is on: a grower who switched the pause off needs to know their probe died at least as much as one who did not. The persistent notification is dismissed and a "back online" push sent when the tank reads again, but only for an episode that alerted.

The alert does not share the `critical` tier's cooldown. That cooldown is shared with the Bayesian environment alerts, so an unrelated temperature alert could silently mute a dead tank for half an hour — the reason the Light Leak Guard got a tier of its own. Like that guard, the tank watch alerts once per episode and owns its own rate limit: a new episode's alert waits out 60 minutes from the previous one, so a probe that drops for twelve minutes every hour does not page every hour, and an episode still running when that wait ends alerts then rather than never.

The validity rules live in `domain/sensor_validity.py`, the module #789 names for every control input. This decision builds only its tank slice; the moisture, pore-EC and climate inputs extend the same module rather than growing a second one. Readers of tank levels that only analyse — [[Tank-Derived Water Mode]] and depletion prediction — are unchanged: they move no water.
