# SubstrateTracker persists live-detected events instead of querying the recorder

Measured crop-steering metrics (overnight dryback, in-cycle P2 drybacks, EC trend) come from a per-growspace SubstrateTracker fed by the existing VWC minute loop, which detects peaks/troughs/shot responses as they happen and persists a rolling event history on the growspace model — following the TankWaterTracker precedent. The HA recorder is *not* queried for any automation or analytics value; it remains chart-only (`crop_steering_history.py`).

The recorder alternative was rejected because: (1) recorder retention and purge settings are user-controlled and outside the integration's contract — a 3-day purge window would silently destroy dryback history; (2) recorder queries are executor-job-expensive and unsuitable for the minute loop's real-time decisions; (3) event detection on live readings is deterministic and unit-testable with plain value sequences, whereas reconstructing peaks from bucketed significant-states is lossy. The cost accepted is a second source of truth for substrate history (tracker events vs. recorder states) and a storage schema that must be migrated if event semantics change — which is why event semantics (shot-to-shot overnight dryback bounds, absolute-VWC-point dryback units) were pinned in CONTEXT.md before implementation.
