# Durable Activity Facts feed idempotent Grow Run projections

Every successful cultivation mutation durably emits one uniquely identified Activity Fact before reporting success, and Grow Run timelines and summaries consume those facts through retryable idempotent projections. A projection failure therefore cannot lose Plant movement, water, alerts, or configuration history and a retry cannot double-count them. Direct best-effort writes from each mutation into a separate Run store were rejected because the existing Plant, Growspace, and auxiliary stores do not provide a cross-file transaction; failing the cultivation action after its primary state had already persisted would be equally dishonest. The accepted cost is a durable outbox, command identities, and projection reconciliation in exchange for recoverable cross-store history without coupling user-facing cultivation latency to every summary update.
